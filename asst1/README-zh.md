### 程序3，第1部分：一些ISPC基础知识（20分中的10分）###

阅读ISPC代码时，您必须牢记，尽管代码看起来很像C/C++代码，但ISPC的执行模型与标准C/C++不同。与C语言不同，ISPC程序的多个程序实例总是在CPU的SIMD执行单元上并行执行。同时执行的程序实例数量由编译器决定（并针对底层机器具体选择）。ISPC程序员可以通过内置变量`programCount`访问这个并发实例的数量。ISPC代码可以通过内置的`programIndex`引用自己的程序实例标识符。因此，从C代码调用ISPC函数可以被认为是生成一组并发的ISPC程序实例（在ISPC文档中称为gang）。这组实例运行到完成，然后控制权返回给调用方的C代码。

以下示例使用常规C代码和ISPC代码的组合来将两个包含1024个元素的向量相加。正如我们在课堂上讨论的，由于gang中的每个实例都是独立的并且执行完全相同的程序逻辑，因此可以通过使用SIMD指令的实现来加速执行。

下面给出了一个简单的ISPC程序。以下C代码将调用以下ISPC代码：

    ------------------------------------------------------------------------
    C程序代码：myprogram.cpp
    ------------------------------------------------------------------------
    const int TOTAL_VALUES = 1024;
    float a[TOTAL_VALUES];
    float b[TOTAL_VALUES];
    float c[TOTAL_VALUES]
 
    // 在这里初始化数组a和b。
   
    sum(TOTAL_VALUES, a, b, c);
 
    // 从sum返回后，a + b的结果存储在c中。

相应的ISPC代码：

    ------------------------------------------------------------------------
    ISPC代码：myprogram.ispc
    ------------------------------------------------------------------------
    export sum(uniform int N, uniform float* a, uniform float* b, uniform float* c)
    {
      // 假设programCount能整除N。
      for (int i=0; i<N; i+=programCount)
      {
        c[programIndex + i] = a[programIndex + i] + b[programIndex + i];
      }
    }

上面的ISPC程序代码将数组元素的处理交织到不同的程序实例中。注意与程序1的相似性，在程序1中您将图像的部分静态分配给了线程。

然而，与其思考如何在程序实例之间划分工作（即工作如何映射到执行单元），通常更方便且更强大的做法是只关注如何将问题分解为独立的部分。ISPC的`foreach`构造提供了一种表达问题分解的机制。下面，ISPC函数`sum2`中的`foreach`循环定义了一个迭代空间，其中所有迭代都是独立的，因此可以按任意顺序执行。ISPC处理将循环迭代分配给并发的程序实例。下面的`sum`和`sum2`之间的区别很微妙，但非常重要。`sum`是命令式的：它描述了如何将工作映射到并发实例。下面的示例是声明式的：它只指定了要执行的工作集。

    -------------------------------------------------------------------------
    ISPC代码：
    -------------------------------------------------------------------------
    export sum2(uniform int N, uniform float* a, uniform float* b, uniform float* c)
    {
      foreach (i = 0 ... N)
      {
        c[i] = a[i] + b[i];
      }
    }

## 程序4：迭代求平方根（15分）##

程序4是一个ISPC程序，它计算2000万个介于0和3之间的随机数的平方根。它使用牛顿法的一个快速迭代实现来求解方程 ${\frac{1}{x^2}} - S = 0$。在此实现中，使用值1.0作为初始猜测。下图显示了`sqrt`收敛到精确解所需的迭代次数（针对(0-3)范围内的数值）。（该实现对该范围之外的输入不收敛）。请注意，收敛速度取决于初始猜测的准确性。

注意：这个问题是对您理解的一次复习检查，因为它涵盖了与程序2和3类似的概念。

![sqrt的收敛性](handout-images/sqrt_graph.jpg "在范围0-3上，初始猜测为1.0时sqrt的收敛性。注意，对于输入值1，收敛立即完成，当输入值趋向0或3时，收敛所需的迭代次数增加（最高值对应输入3）。")

**您需要做什么：**

1. 构建并运行`sqrt`。报告ISPC实现在单CPU核心（无任务）和使用所有核心（有任务）时的加速比。由于SIMD并行化带来的加速比是多少？由于多核并行化带来的加速比是多少？
2. 修改数组`values`的内容，以提高ISPC实现的相对加速比。构建一个特定的输入，使__相对于代码的串行版本加速比最大化__，并报告所获得的加速比（对于有任务和无任务的ISPC实现都是如此）。您的修改是否提高了SIMD加速比？是否提高了多核加速比（即从无任务ISPC转移到有任务ISPC所带来的收益）？请解释原因。
3. 为`sqrt`构建一个特定的输入，使ISPC（无任务）相对于代码串行版本的加速比__最小化__。描述这个输入，说明您为什么选择它，并报告ISPC实现得到的相对性能。效率损失的原因是什么？
   __（请记住，我们为ISPC使用 `--target=avx2` 选项，该选项生成8路SIMD指令）__。
4.  _附加分：（最多2分）_ 使用AVX2内联函数手动编写您自己的`sqrt`函数版本。要获得学分，您的实现应几乎与使用ISPC生成的二进制文件一样快（或更快）。您可能会发现[Intel Intrinsics Guide](https://software.intel.com/sites/landingpage/IntrinsicsGuide/)非常有帮助。

## 程序5：BLAS `saxpy`（10分）##

程序5是BLAS（基本线性代数子程序）库中saxpy例程的一个实现，该库在许多系统上被广泛使用（并经过高度优化）。`saxpy`计算简单的操作`result = scale*X+Y`，其中`X`、`Y`和`result`是包含`N`个元素的向量（在程序5中，`N` = 2000万），`scale`是一个标量。请注意，`saxpy`每使用三个元素执行两次数学运算（一次乘法，一次加法）。`saxpy`是一种*琐碎的并行化计算*，具有可预测的、规则的数据访问和可预测的执行成本。

**您需要做什么：**

1. 编译并运行`saxpy`。程序将报告saxpy的ISPC（无任务）和ISPC（有任务）实现的性能。您观察到了使用ISPC有任务带来的什么加速比？解释这个程序的性能。您认为它可以被大幅度改进吗？（例如，您能否重写代码以实现接近线性的加速比？是或否？请证明您的答案。）
2. __附加分：__（1分）请注意，`main.cpp`中计算消耗的总内存带宽为 `TOTAL_BYTES = 4 * N * sizeof(float);`。尽管`saxpy`从X加载一个元素，从Y加载一个元素，并将一个元素写入`result`，但乘以4是正确的。为什么？（提示：考虑CPU缓存的工作原理。）
3. __附加分：__（分数根据具体情况而定）提高`saxpy`的性能。我们期待的是一种显著的加速，而不仅仅是几个百分点。如果成功，请描述您的实现方法以及在这些系统上可能达到的最佳性能。另外，如果成功，请告诉助教，我们会很感兴趣。;-)

注：过去有些学生在这个问题上纠结（想得太复杂）。我们期望一个简单的答案，但运行这个问题得到的结果可能会引发您更多的思考。欢迎来和助教讨论。

## 程序6：加速K-Means（15分）##

程序6使用K-Means数据聚类算法对一百万个数据点进行聚类（[维基百科](https://en.wikipedia.org/wiki/K-means_clustering)，[CS 221讲义](https://stanford.edu/~cpiech/cs221/handouts/kmeans.html)）。如果您不熟悉该算法，不要担心！具体细节对练习并不重要，但从高层次来看，给定K个起始点（聚类质心），算法迭代更新质心直到满足收敛条件。结果可以在下面的图像中看到，这些图像描绘了算法在程序开始和结束时的状态，其中红色星号是聚类质心，数据点的颜色对应聚类分配。

![K-Means起点和终点](./handout-images/kmeans.jpg "适用于二维数据的K-Means算法的起点和终点。")

在您获得的起始代码中，K-means算法的实现是正确的，但当前状态的速度还不够快。这就是您需要发挥作用的地方！您的任务是找出实现中**需要改进的地方**以及**如何改进**。您将在此问题中练习的关键技能是__隔离性能热点__。我们不会告诉您去哪里查看代码。您需要自己找出来。您的第一个想法应该是……代码在哪里花费了最多的时间，您应该在源代码中插入计时代码来进行测量。基于这些测量，您应该专注于花费了显著运行时间的那部分代码，然后更仔细地理解它，以确定是否有办法加速它。

**您需要做什么：**

1. 使用命令 `ln -s /afs/ir.stanford.edu/class/cs149/data/data.dat ./data.dat` 在当前目录中创建指向数据集的符号链接（确保您在`prog6_kmeans`目录中）。这是一个大文件（约800MB），因此这是访问它的首选方式。但是，如果您想要本地副本，可以在您的个人机器上运行此命令 `scp [Your SUNetID]@myth[51-66].stanford.edu:/afs/ir.stanford.edu/class/cs149/data/data.dat ./data.dat`。获取数据后，编译并运行`kmeans`（首次运行时程序加载数据可能需要比平时更长的时间）。程序将报告算法在数据上的总运行时间。
2. 运行 `pip install -r requirements.txt` 下载必要的绘图包。接下来，尝试运行 `python3 plot.py`，它将从运行`kmeans`生成的日志（"start.log"和"end.log"）生成文件"start.png"和"end.png"。这些文件将出现在当前目录中，应该与上面的图像类似。__警告：您可能会注意到并非所有点都分配给了"最近的"质心。这没关系。__（对于那些想理解原因的人：我们使用[PCA](https://en.wikipedia.org/wiki/Principal_component_analysis)将100维数据点投影到2维以生成这些可视化。因此，虽然100维数据点在高维空间中靠近适当的质心，但数据点和质心的投影在2维中可能彼此不接近。）只要聚类看起来"合理"（使用步骤2中起始代码生成的图像作为参考），并且大多数点看起来分配给了最近的质心，代码仍然是正确的。
3. 使用`common/CycleTimer.h`中的计时函数来确定代码中存在性能瓶颈的位置。您需要调用`CycleTimer::currentSeconds()`，它返回当前时间（以秒为单位）作为浮点数。代码中大部分时间花费在哪里？
4. 根据上一步的发现，改进实现。我们期望获得约2.1倍或更高的加速比（即 $\frac{旧运行时间}{新运行时间} \ge 2.1$）。请解释您是如何得出解决方案的，以及您的最终解决方案是什么和相关的加速比。该过程的实验报告应描述一系列步骤。我们期望的形式是："我测量了……这让我相信X。因此，为了改进，我尝试了……，结果获得了……的加速/减速。"

约束条件：
- 您只能修改`kmeansThread.cpp`中的代码。您不能修改`stoppingConditionMet`函数，也不能更改`kMeansThread`的接口，但其他任何内容都是公平的（例如，您可以向`WorkerArgs`结构体添加新成员、重写函数、分配新数组等）。但是……
