## 概述

本作业是一个开放式作业，与 CS149 之前编程作业稍有不同。我们希望你将其看作一个简短的期末项目，我们已校准过，大约花费两个晚上的工作就能获得不错的分数。但我们也将其设计成让那些真正想深入钻研的团队能够在现代高端 GPU 上投入大量时间追求**极快代码实现**。没有单一的任务需要优化，也没有性能门槛决定你的分数。相反，我们要求你从我们提供的一系列 AI 相关内核中选择一个（或多个），然后为 H100 GPU 生成一个优化实现。（所有内核在 PyTorch 中都有基线实现。）

为了增添趣味性，也为了帮助你了解自己的实现相对于班上其他同学的水平，我们将为每个内核运行一个班级排行榜，你将可以看到你的实现速度与同学相比如何！

总而言之，在本作业中：

* 你可以选择自己想要优化的算法（请查看下面选项的详细信息）
* 你将在 H100 GPU 上运行代码，当然，如果团队在 PA4 中还有剩余积分，也欢迎在 Trainium 上优化算法（不过 Trainium 没有排行榜）。
* 你可以选择使用纯 CUDA 编写代码，或者使用 [Triton](https://triton-lang.org/main/index.html) 或 [Tilelang](https://tilelang.com/) —— 两种现代 AI 框架，它们提供了基于图块的抽象来编写 AI 算法。
* **你可以以任何方式使用 [Stanford's AI Playground](https://uit.stanford.edu/service/aiplayground) 中可访问的任何 LLM 来辅助完成作业。** 例如，你可以使用 LLM 编写代码、评估性能分析器的结果以决定下一步行动等。
* 没有特定的性能要求与分数挂钩……事实上，我们希望一些团队的表现能比世界上一些最好的实现好得多（尤其是在有 LLM 帮助的情况下！）。相反，你的分数将由助教根据你提交的工作日志来评定，该日志描述了你优化过程中为获得最终（最快）结果所做的一系列选择。我们在后面的说明中描述了工作日志的具体要求。

总体目标是练习开放式的性能工程，就像你在“真实世界”中试图让程序跑得更快，而没有现成的快速参考实现可供追赶时遇到的情况一样。

## 设置与作业队列使用指南（如何运行代码）

在本作业中，你不会自己运行云中的 GPU 实例，而是本地开发并将代码提交到一个队列，该队列将在由课程团队管理的 H100 机器上运行你的代码。当你的作业完成后，你将收到控制台日志形式的运行结果、性能结果，以及一个（可选的）性能分析报告，该报告记录了作业的关键性能统计数据。性能分析报告将帮助你做出优化决策。

以下指南将引导你安装 popcorn-cli（用于向作业队列提交作业的工具）、使用 SUNet 用户名注册系统、开发和测试内核，以及将结果提交到各个内核的排行榜。请按顺序执行以下步骤：安装、一次性注册、本地开发（可选）以及作业提交——以确保你的工作流程在提供的环境和你自己的 GPU 机器上都能顺利运行。

### 步骤 4：开发你的解决方案

每个问题在 `/problems` 下都有一个文件夹。每个问题文件夹内有一个 `templates/` 文件夹和一个 `test_cases/` 文件夹。`templates/template.py` 提供了一个用 Python 编写的示例提交，`templates/template.cu` 提供了一个用 CUDA 编写的示例提交。

#### 使用 Python、Triton、TileLang 编写

如果你希望用 Python 编写解决方案，请在相应的问题文件夹中创建 `submission.py`。你的实现需要遵循 `/templates/template.py` 中的 `custom_kernel` 接口。

我们的作业队列提交环境支持 [Triton](https://triton-lang.org/main/index.html) 和 [Tilelang](https://tilelang.com/)（Triton 3.5.1，Tilelang 0.1.6.post2）。因此，你可以自由地使用这些现代特定领域框架中的任何一种来编写 AI 内核。

#### 使用 CUDA 编写

如果你希望直接用 CUDA 编写解决方案，请在每个问题文件夹下遵循 `/templates/template.cu` 中给出的代码骨架模式创建 `submission.cu`。内核的 PyTorch 绑定在 `wrap_cuda_submission.py` 中。

**重要**：由于 H100 作业队列只接受 `submission.py` 作为你的代码，你需要运行 `python wrap_cuda_submission.py <SUNet ID>` 来将你的 CUDA 代码包装到 `submission.cu` 中（以便编译并链接到 PyTorch）。请在使用 `popcorn-cli` 提交或使用 `eval.py` 本地运行之前执行此操作。

#### 在 GPU 机器上进行本地开发

**如果你不希望在自己的机器上运行代码，可以跳过本节。**

你可以通过本地编辑代码并使用作业队列运行作业来开发，也可以在支持 CUDA 的 NVIDIA GPU 机器上（例如 AWS `g6.xlarge`（NVIDIA L4 GPU），如果你还有剩余积分的话）本地开发和运行你的解决方案。但是，在其他机器上的开发应仅用于正确性验证和探索选项。我们希望你在 H100 上调整性能，并报告你在 H100 上的分析结果。正如你在本课程中学到的，为一种处理器做出的决策可能不是另一种处理器的最佳决策。如果你大部分时间都在较小的 GPU 上开发，请注意这一点。

以下是在 `g6.xlarge` 上使用 `Deep Learning OSS Nvidia Driver AMI GPU PyTorch 2.8 (Ubuntu 24.04)` AMI 设置本地开发环境的示例。

```
source /opt/pytorch/bin/activate # 激活包含 PyTorch 的环境。 
export PYTHONPATH="<asst5路径>/problems:$PYTHONPATH"
```

然后，在 `/problem/<fd/swiglu/histogram>` 文件夹中运行命令：
```
python ../eval.py <test/benchmark/profile> test_cases/test.txt
```
`test.txt` 可以更改为任何你想要测试的形状，只需遵循格式即可。我们将只在一组形状上进行基准测试和测试。

如果设置了 `profile` 选项，`eval.py` 会使用 `ncu` 工具和 `ncu_report` Python 包。

`ncu` 需要操作系统对 GPU 设备性能计数器的权限。要启用此功能，请按照[此处](https://developer.nvidia.com/nvidia-development-tools-solutions-err_nvgpuctrperm-permission-issue-performance-counters)的“为所有用户启用访问权限”部分中的说明进行操作。只需执行一次。示例命令如下：
```
cd /etc/modprobe.d
sudo vim ncu-permission.conf
options nvidia NVreg_RestrictProfilingToAdminUsers=0 # 在 vim 中输入此行
sudo reboot # 重启以使更改生效
```

之后，你需要找到可以找到 nsight-compute 文件夹的 CUDA 安装路径。这是为了 `eval.py` 使用的 `ncu_report` 包。示例命令：
```
export PYTHONPATH="/usr/local/cuda-12.9/nsight-compute-2025.2.1/extras/python:$PYTHONPATH"
```

如果你使用内联 CUDA，并在执行 `eval.py` 时遇到类似 `libstdc++.so.6: version `GLIBCXX_3.4.20' not found` 的错误，请运行：
```
export LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libstdc++.so.6
```

如果 `popcorn-cli` 没有自动添加到 PATH，请执行：
```
sudo chown ubuntu:ubuntu ~/.bashrc
export PATH="<asst5路径/target/release>:$PATH"
```

### 步骤 5：提交你的解决方案

#### 命令格式

```bash
popcorn-cli submit --leaderboard <排行榜名称> --mode <模式> <submission.py 的路径>
```

#### 标志和命令行选项

- `--leaderboard`：班级排行榜的名称（每个问题一个），用于提交。
- `--mode`：提交模式（选择一个）：
  - `test`：验证正确性（不提交排行榜）
  - `benchmark`：评估运行时间（不提交排行榜）
  - `leaderboard`：基准测试并将结果提交到班级排行榜
  - `profile`：分析内核并返回结果（完整的 NCU 报告可作为可下载的工件从运行作业的链接中获得）
- `--output`：[可选] 返回打印结果的输出路径（如果你希望将结果保存到文件中而不是直接打印在终端中）

运行此命令后，你将在终端中获得作业页面的链接。然后你可以访问该页面查看完整信息，包括在 profile 模式下的 `.ncu-rep` 文件。

## 你需要提交的内容 —— 工作日志

在本作业中，你的目标是展示对课程原则的掌握，方法是从一个你不熟悉的代码开始，然后将其性能优化到超越初始实现。你不需要达到某个特定的性能目标，而是尽自己最大努力并展示你的思考过程。因此，我们期望你提交的作业中包含多个不同版本的代码（优化路径上的各个步骤），以及你一路走来的推理过程。

本课程的一个关键原则是数据驱动的代码优化决策。换句话说，性能优化是一个迭代过程，你需要执行以下步骤：

1. 运行当前状态的代码
2. 测量其性能（并从分析器中获取关于计算和带宽利用率的统计数据）
3. 然后，利用你对代码的了解（依赖关系在哪里？数据访问在哪里？）以及测量数据，形成关于如何使代码更快运行的假设（**增加并行度、减少内存流量、隐藏内存延迟、缓解竞争**）
4. 然后，你对代码实现一个更改以测试该假设是否成立，以及你的代码现在是否更快。

注意：在本作业中，你可以使用 LLM 来协助执行步骤（3）和（4）……因此可能不是*你*直接执行这些步骤，而是你提示 LLM 来帮助你完成。

因此，你提交的工作日志应格式化为一系列步骤。

#### 工作日志第一部分：你所采取的步骤

对于每个步骤，我们需要知道：
* 当前步骤的代码是如何组织的？（我们希望您提交代码，但同时也在提交文件中以高层抽象描述，例如：“我们对外层循环进行分块，并将块映射到 CUDA 线程块。内层循环在线程块内的线程上并行化。”）
* 代码的性能如何？（请在提交文件中明确给出运行时间）
* 你还测量了当前代码的哪些其他统计数据，并查看了哪些内容？
* 你从这些测量中得出了什么结论？
* 你认为限制性能的因素是什么（或如何改进）的假设是什么？你是如何得出这个假设的？
* 这个假设建议你下一步应该如何修改代码的设计？

当然，我们不需要阅读你尝试的每一件小事或每一个微小改动。希望你自行判断哪些步骤在你的过程中最重要，我们只希望听到这些。例如，你可以考虑你在 PA2、PA3 和 PA4 的办公时间与助教讨论作业时所用的抽象层次。那就是你在提交文件中应该瞄准的抽象层次。

#### 工作日志第二部分：解释你为什么停止

最后，我们希望你的工作日志末尾提供解释为什么停止的理由！当然，你可能因为觉得已经花了足够多的时间或时间不够而停止，但有些团队可能会决定停止，因为他们从分析结果中得出结论：没有更多可以做的了。如果你是基于结果分析而停止的，我们希望了解你是如何做出这个决定的。

#### 工作日志第三部分：使用 LLM 有帮助吗？

在本作业中，欢迎你使用 LLM 来加速你的开发。如果你使用了 LLM 辅助，请反思你是如何使用 LLM 的：是用来编写代码？头脑风暴优化思路？还是解释分析结果？请评论你是否觉得 LLM 助手有帮助。

**一点说明：** 完全有可能，仅凭一个简单的提示（如“为 H100 优化这段代码”），LLM 就能直接给出其中一个问题的高性能解决方案。（我们当然没有尝试过 [Stanford's AI Playground](https://uit.stanford.edu/service/aiplayground) 上所有的 LLM，也当然没有尝试设计良好的指令提示。）但是，在你的工作日志中，你必须解释你是如何得到你的解决方案的推理过程，以及你是如何断定进一步优化没有太多加速潜力的等等。如果你遇到一种情况，LLM 在第一次提示时就跳到了一个令人惊讶的答案，而你找不到任何让它更好的方法，没关系，请与助教联系，我们可以讨论你应如何继续。例如，你可以尝试第二个问题。

**但要明确的是，一种巧妙的方法是与 LLM 携手迭代工作来振动编码解决方案，或者通过一系列提示工程步骤来获得一个好的答案，这也是一种很好的作业完成方式。只需在你的工作日志中描述你的思考过程和具体操作。例如，你可能希望为每个步骤包含你的 LLM 提示。**
